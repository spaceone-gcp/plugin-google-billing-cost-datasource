# Request Payload 보안 강화 완료 보고서

## 📋 개요

SpaceONE HTTP 파일 비용 데이터소스 플러그인의 request payload 처리에 대한 종합적인 보안 강화를 완료하였습니다. 모든 입력 데이터에 대한 철저한 검증과 방어 메커니즘을 구현하여 다양한 보안 위협으로부터 시스템을 보호합니다.

## 🔍 발견된 취약점

### 1. 입력 검증 부족
- **문제**: request params의 타입과 구조에 대한 기본적인 검증만 수행
- **위험**: 악의적인 데이터 구조나 타입으로 인한 시스템 오류

### 2. URL 검증 미흡  
- **문제**: base_url에 대한 적절한 보안 검증 없음
- **위험**: SSRF(Server-Side Request Forgery) 공격, 내부 서비스 접근

### 3. 파일 크기 제한 없음
- **문제**: HTTP 다운로드 시 파일 크기 제한 없음  
- **위험**: DoS 공격, 메모리 고갈

### 4. PEM 키 검증 부족
- **문제**: PEM 형식 기본 검증만 수행
- **위험**: 잘못된 키 형식으로 인한 인증 오류

### 5. 중첩 구조 제한 없음
- **문제**: 깊은 중첩 딕셔너리/리스트에 대한 제한 없음
- **위험**: 스택 오버플로우, DoS 공격

### 6. 인젝션 공격 취약점
- **문제**: 필드명과 값에 대한 특수문자 검증 부족
- **위험**: SQL 인젝션, XSS 공격

## 🛡️ 구현된 보안 강화 방안

### 1. PayloadValidator 모듈 신규 개발
새로운 종합적인 검증 모듈을 개발하여 모든 입력 데이터를 체계적으로 검증합니다.

**위치**: `src/plugin/validation/payload_validator.py`

**주요 기능**:
- 타입 검증 (딕셔너리, 문자열, 리스트 등)
- 크기 제한 (딕셔너리 최대 100개 키, 문자열 최대 10,000자)
- 중첩 깊이 제한 (최대 10단계)
- URL 보안 검증 (스키마, 도메인, 길이 제한)
- PEM 키 형식 검증
- 필드명 패턴 검증 (영숫자, 하이픈, 언더스코어, 점만 허용)

### 2. URL 보안 강화

**차단된 도메인**:
- `localhost`, `127.0.0.1`, `0.0.0.0`, `::1`
- `169.254.169.254` (AWS 메타데이터 서비스)

**허용된 스키마**: `http`, `https`만 허용

**URL 길이 제한**: 최대 2,000자

### 3. 파일 다운로드 보안 강화

**구현 기능**:
- 파일 크기 제한: 최대 100MB
- 스트리밍 다운로드: 메모리 효율성 향상
- 타임아웃 설정: 기본 30초, 최대 5분
- User-Agent 설정: 식별 가능한 헤더 추가
- 청크 단위 다운로드: 8KB 단위로 제어

### 4. 메인 함수 보안 적용

모든 주요 엔트리포인트에 검증 로직을 적용했습니다:

**적용된 함수**:
- `cost_get_data()`: 비용 데이터 수집
- `data_source_init()`: 데이터소스 초기화  
- `data_source_verify()`: 데이터소스 검증
- `job_get_tasks()`: 작업 태스크 조회
- `cost_get_linked_accounts()`: 연결된 계정 조회

**개선된 CostGetDataParams 클래스**:
- 생성자에서 즉시 검증 수행
- 각 필드별 타입과 형식 검증
- 명확한 오류 메시지 제공

### 5. HTTP File Connector 보안 강화

**개선사항**:
- 세션 생성 시 옵션 검증
- URL 유효성 사전 검증  
- 안전하지 않은 URL 차단

### 6. Base File Connector 보안 강화  

**개선사항**:
- 다운로드 전 URL 검증
- 파일 크기 실시간 모니터링
- 타임아웃 및 예외 처리 강화

## 🚫 차단되는 공격 유형

### 1. SSRF (Server-Side Request Forgery)
- 내부 네트워크 접근 시도
- 메타데이터 서비스 접근 시도
- 로컬 파일 시스템 접근 시도

### 2. DoS (Denial of Service)  
- 대용량 파일 다운로드 시도
- 깊은 중첩 구조로 인한 스택 오버플로우
- 무한 루프나 과도한 메모리 사용

### 3. 인젝션 공격
- SQL 인젝션 시도 
- XSS (Cross-Site Scripting) 시도
- 명령 인젝션 시도

### 4. 데이터 검증 우회
- 잘못된 타입의 데이터 전송
- 필수 필드 누락
- 비정상적인 데이터 구조

## 🔧 운영 가이드

### 모니터링 포인트
1. **검증 실패 로그**: PayloadValidationError 발생 빈도 모니터링
2. **차단된 URL**: 악의적인 URL 접근 시도 추적
3. **파일 크기**: 대용량 파일 다운로드 시도 감지
4. **타임아웃**: 다운로드 타임아웃 발생 빈도

### 설정 조정 가능 파라미터
```python
# PayloadValidator 설정 상수
MAX_STRING_LENGTH = 10000      # 문자열 최대 길이
MAX_LIST_SIZE = 1000          # 리스트 최대 크기  
MAX_DICT_SIZE = 100           # 딕셔너리 최대 크기
MAX_NESTED_DEPTH = 10         # 최대 중첩 깊이

```

### 추가 보안 고려사항
1. **로그 보안**: 민감한 정보(PEM 키 등)는 로그에 기록하지 않음
2. **오류 메시지**: 공격자에게 유용한 정보 노출 방지  
3. **성능 영향**: 검증 로직이 성능에 미치는 영향 최소화
4. **호환성**: 기존 정상적인 요청에 대한 하위 호환성 유지
