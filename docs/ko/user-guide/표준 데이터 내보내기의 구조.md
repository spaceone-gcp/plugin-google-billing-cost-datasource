# 표준 데이터 내보내기의 구조

이 문서는 Google Cloud의 공식 [표준 데이터 내보내기의 구조](https://cloud.google.com/billing/docs/how-to/export-data-bigquery-tables/standard-usage?hl=ko) 가이드를 기반으로, 표준 사용량 비용 데이터의 상세한 스키마와 각 필드의 의미를 설명합니다.

## 📋 개요

**표준 사용량 비용 데이터**는 Google Cloud Billing Export의 기본 형태로, 계정, 프로젝트, 서비스, SKU 수준에서의 비용 정보를 제공합니다. 이는 대부분의 비용 분석과 보고서 작성에 충분한 정보를 담고 있습니다.

### 테이블 정보
- **테이블명**: `gcp_billing_export_v1_<BILLING_ACCOUNT_ID>`
- **생성 조건**: 표준 사용량 비용 데이터 내보내기 활성화
- **업데이트 주기**: 일 1-2회
- **파티셔닝**: `usage_start_time` 필드로 일 단위 파티셔닝

## 📊 스키마 구조

### 1. 청구 계정 정보 (Billing Account)

| 필드명 | 타입 | 설명 | 활용 예시 |
|:---|:---|:---|:---|
| `billing_account_id` | `STRING` | 청구 계정 ID | 다중 계정 환경에서 계정별 비용 분리 |

```sql
-- 청구 계정별 월간 비용
SELECT 
  billing_account_id,
  FORMAT_DATE('%Y-%m', DATE(usage_start_time)) as month,
  SUM(cost) as monthly_cost
FROM `project.dataset.gcp_billing_export_v1_XXXXXX`
GROUP BY 1, 2
ORDER BY 2 DESC, 3 DESC;
```

### 2. 서비스 정보 (Service)

| 필드명 | 타입 | 설명 | 활용 예시 |
|:---|:---|:---|:---|
| `service.id` | `STRING` | Google Cloud 서비스의 고유 ID | API를 통한 서비스 식별 |
| `service.description` | `STRING` | 서비스 이름 (예: "Compute Engine") | 사용자 친화적인 보고서 작성 |

```sql
-- 서비스별 비용 순위
SELECT 
  service.description as service_name,
  SUM(cost) as total_cost,
  ROUND(SUM(cost) / SUM(SUM(cost)) OVER() * 100, 2) as cost_percentage
FROM `project.dataset.gcp_billing_export_v1_XXXXXX`
WHERE DATE(usage_start_time) >= DATE_SUB(CURRENT_DATE(), INTERVAL 30 DAY)
GROUP BY service_name
ORDER BY total_cost DESC;
```

### 3. SKU 정보 (Stock Keeping Unit)

| 필드명 | 타입 | 설명 | 활용 예시 |
|:---|:---|:---|:---|
| `sku.id` | `STRING` | SKU의 고유 ID | 정확한 리소스 유형 식별 |
| `sku.description` | `STRING` | SKU 설명 (예: "N1 Standard Instance Core") | 상세한 비용 분석 |

```sql
-- Compute Engine 인스턴스 타입별 비용
SELECT 
  sku.description as sku_name,
  SUM(cost) as total_cost,
  SUM(usage.amount) as total_usage,
  ROUND(SUM(cost) / NULLIF(SUM(usage.amount), 0), 4) as cost_per_unit
FROM `project.dataset.gcp_billing_export_v1_XXXXXX`
WHERE service.description = 'Compute Engine'
  AND sku.description LIKE '%Instance Core%'
  AND DATE(usage_start_time) >= DATE_SUB(CURRENT_DATE(), INTERVAL 7 DAY)
GROUP BY sku_name
ORDER BY total_cost DESC;
```

### 4. 프로젝트 정보 (Project)

| 필드명 | 타입 | 설명 | 활용 예시 |
|:---|:---|:---|:---|
| `project.id` | `STRING` | 프로젝트 ID | 프로젝트별 비용 추적 |
| `project.name` | `STRING` | 프로젝트 이름 | 사용자 친화적인 보고서 |
| `project.labels` | `RECORD` | 프로젝트 라벨 (키-값 쌍) | 조직 구조에 따른 비용 분류 |
| `project.ancestry_numbers` | `STRING` | 프로젝트 계층 구조 | 조직/폴더 수준 비용 집계 |

```sql
-- 환경별 프로젝트 비용 (라벨 기반)
SELECT 
  (SELECT value FROM UNNEST(project.labels) WHERE key = 'environment') as environment,
  (SELECT value FROM UNNEST(project.labels) WHERE key = 'team') as team,
  COUNT(DISTINCT project.id) as project_count,
  SUM(cost) as total_cost
FROM `project.dataset.gcp_billing_export_v1_XXXXXX`
WHERE DATE(usage_start_time) >= DATE_SUB(CURRENT_DATE(), INTERVAL 30 DAY)
GROUP BY environment, team
ORDER BY total_cost DESC;
```

### 5. 사용량 정보 (Usage)

| 필드명 | 타입 | 설명 | 활용 예시 |
|:---|:---|:---|:---|
| `usage.amount` | `FLOAT` | 사용량 | 리소스 소비량 분석 |
| `usage.unit` | `STRING` | 사용량 단위 (예: "hour", "byte-seconds") | 단위당 비용 계산 |
| `usage.amount_in_pricing_units` | `FLOAT` | 가격 책정 단위로 표시된 사용량 | 정확한 비용 계산 |
| `usage.pricing_unit` | `STRING` | 가격 책정 단위 | 가격 정보와의 매핑 |

```sql
-- 시간당 Compute Engine 사용률 분석
SELECT 
  EXTRACT(HOUR FROM usage_start_time) as hour_of_day,
  SUM(usage.amount) as total_core_hours,
  SUM(cost) as total_cost,
  COUNT(DISTINCT project.id) as active_projects
FROM `project.dataset.gcp_billing_export_v1_XXXXXX`
WHERE service.description = 'Compute Engine'
  AND sku.description LIKE '%Instance Core%'
  AND DATE(usage_start_time) = CURRENT_DATE() - 1
GROUP BY hour_of_day
ORDER BY hour_of_day;
```

### 6. 비용 정보 (Cost)

| 필드명 | 타입 | 설명 | 활용 예시 |
|:---|:---|:---|:---|
| `cost` | `FLOAT` | 실제 청구 금액 (크레딧 적용 후) | 최종 지불 비용 |
| `currency` | `STRING` | 통화 코드 (예: "USD", "KRW") | 다중 통화 환경 처리 |
| `currency_conversion_rate` | `FLOAT` | 환율 | 기준 통화로 환산 |
| `cost_at_list` | `FLOAT` | 정가 (크레딧 적용 전) | 할인 효과 분석 |

```sql
-- 월별 할인 효과 분석
SELECT 
  FORMAT_DATE('%Y-%m', DATE(usage_start_time)) as month,
  SUM(cost_at_list) as list_price,
  SUM(cost) as actual_cost,
  SUM(cost_at_list) - SUM(cost) as total_savings,
  ROUND((1 - SUM(cost) / NULLIF(SUM(cost_at_list), 0)) * 100, 2) as discount_percentage
FROM `project.dataset.gcp_billing_export_v1_XXXXXX`
WHERE cost_at_list > 0
GROUP BY month
ORDER BY month DESC;
```

### 7. 시간 정보 (Time)

| 필드명 | 타입 | 설명 | 활용 예시 |
|:---|:---|:---|:---|
| `usage_start_time` | `TIMESTAMP` | 사용 시작 시간 | 실제 리소스 사용 기간 분석 |
| `usage_end_time` | `TIMESTAMP` | 사용 종료 시간 | 사용 기간 계산 |
| `export_time` | `TIMESTAMP` | 데이터 내보내기 시간 | 데이터 신선도 확인 |

```sql
-- 주말 vs 평일 사용 패턴
SELECT 
  CASE 
    WHEN EXTRACT(DAYOFWEEK FROM usage_start_time) IN (1, 7) THEN 'Weekend'
    ELSE 'Weekday'
  END as day_type,
  SUM(cost) as total_cost,
  AVG(cost) as avg_cost,
  COUNT(*) as record_count
FROM `project.dataset.gcp_billing_export_v1_XXXXXX`
WHERE DATE(usage_start_time) >= DATE_SUB(CURRENT_DATE(), INTERVAL 30 DAY)
GROUP BY day_type;
```

### 8. 위치 정보 (Location)

| 필드명 | 타입 | 설명 | 활용 예시 |
|:---|:---|:---|:---|
| `location.location` | `STRING` | 위치 (예: "us-central1-a") | 상세 위치별 비용 |
| `location.country` | `STRING` | 국가 코드 | 국가별 비용 분석 |
| `location.region` | `STRING` | 리전 (예: "us-central1") | 리전별 비용 최적화 |
| `location.zone` | `STRING` | 존 (예: "us-central1-a") | 가용성 존별 분산 분석 |

```sql
-- 리전별 비용 및 성능 분석
SELECT 
  location.region,
  location.country,
  SUM(cost) as total_cost,
  COUNT(DISTINCT project.id) as project_count,
  SUM(usage.amount) as total_usage
FROM `project.dataset.gcp_billing_export_v1_XXXXXX`
WHERE service.description = 'Compute Engine'
  AND DATE(usage_start_time) >= DATE_SUB(CURRENT_DATE(), INTERVAL 30 DAY)
GROUP BY location.region, location.country
ORDER BY total_cost DESC;
```

### 9. 크레딧 정보 (Credits)

| 필드명 | 타입 | 설명 | 활용 예시 |
|:---|:---|:---|:---|
| `credits` | `RECORD` (반복) | 적용된 크레딧 배열 | 할인 상세 분석 |
| `credits.name` | `STRING` | 크레딧 이름 | 크레딧 유형별 분석 |
| `credits.type` | `STRING` | 크레딧 유형 | 할인 정책 효과 측정 |
| `credits.amount` | `FLOAT` | 크레딧 금액 (음수) | 절약 금액 계산 |
| `credits.id` | `STRING` | 크레딧 ID | 크레딧 추적 |

```sql
-- 크레딧 유형별 절약 효과
SELECT 
  c.type as credit_type,
  c.name as credit_name,
  COUNT(*) as applications,
  SUM(c.amount) as total_credit_amount,
  COUNT(DISTINCT project.id) as benefited_projects
FROM `project.dataset.gcp_billing_export_v1_XXXXXX`,
     UNNEST(credits) as c
WHERE DATE(usage_start_time) >= DATE_SUB(CURRENT_DATE(), INTERVAL 30 DAY)
  AND c.amount < 0
GROUP BY credit_type, credit_name
ORDER BY total_credit_amount ASC;  -- 음수이므로 ASC가 큰 절약
```

### 10. 인보이스 정보 (Invoice)

| 필드명 | 타입 | 설명 | 활용 예시 |
|:---|:---|:---|:---|
| `invoice.month` | `STRING` | 인보이스 월 (YYYYMM) | 청구서 기준 집계 |
| `cost_type` | `STRING` | 비용 유형 (REGULAR, TAX, ADJUSTMENT) | 세금/조정 분리 분석 |

```sql
-- 인보이스 월별 비용 유형 분석
SELECT 
  invoice.month,
  cost_type,
  SUM(cost) as total_cost,
  COUNT(*) as record_count
FROM `project.dataset.gcp_billing_export_v1_XXXXXX`
WHERE invoice.month >= FORMAT_DATE('%Y%m', DATE_SUB(CURRENT_DATE(), INTERVAL 6 MONTH))
GROUP BY invoice.month, cost_type
ORDER BY invoice.month DESC, cost_type;
```

### 11. 라벨 정보 (Labels)

| 필드명 | 타입 | 설명 | 활용 예시 |
|:---|:---|:---|:---|
| `labels` | `RECORD` (반복) | 리소스 라벨 배열 | 리소스 분류 및 추적 |
| `labels.key` | `STRING` | 라벨 키 | 라벨 기반 필터링 |
| `labels.value` | `STRING` | 라벨 값 | 라벨 값별 집계 |

```sql
-- 라벨 기반 비용 할당 분석
SELECT 
  (SELECT value FROM UNNEST(labels) WHERE key = 'cost-center') as cost_center,
  (SELECT value FROM UNNEST(labels) WHERE key = 'application') as application,
  SUM(cost) as allocated_cost,
  COUNT(DISTINCT project.id) as project_count
FROM `project.dataset.gcp_billing_export_v1_XXXXXX`
WHERE DATE(usage_start_time) >= DATE_SUB(CURRENT_DATE(), INTERVAL 30 DAY)
GROUP BY cost_center, application
HAVING cost_center IS NOT NULL
ORDER BY allocated_cost DESC;
```

## 🔍 표준 데이터의 한계점

### 리소스 수준 정보 부족
- **개별 리소스 식별 불가**: VM 인스턴스, 디스크 등의 개별 이름 정보 없음
- **리소스별 비용 추적 제한**: 동일 SKU 내에서 개별 리소스 구분 어려움

### 상세 라벨 정보 제한
- **모든 라벨 포함 안 됨**: 일부 시스템 라벨이나 상세 태그 정보 누락
- **태그 정보 부재**: 리소스 태그 정보는 상세 데이터에서만 제공

### 해결 방안
상세한 분석이 필요한 경우 **상세 사용량 비용 데이터**를 활용하세요:

## 📈 표준 데이터 활용 모범 사례

### 1. 효율적인 쿼리 패턴

```sql
-- 좋은 예: 파티션 필터 + 집계
SELECT 
  service.description,
  SUM(cost) as total_cost
FROM `project.dataset.gcp_billing_export_v1_XXXXXX`
WHERE DATE(usage_start_time) = '2024-01-15'  -- 파티션 필터
GROUP BY 1
ORDER BY 2 DESC;

-- 피해야 할 예: 파티션 필터 없는 전체 스캔
SELECT service.description, cost
FROM `project.dataset.gcp_billing_export_v1_XXXXXX`
WHERE cost > 100;  -- 비효율적
```

### 2. 월별 트렌드 분석

```sql
-- 서비스별 월별 성장률 분석
WITH monthly_costs AS (
  SELECT 
    service.description,
    FORMAT_DATE('%Y-%m', DATE(usage_start_time)) as month,
    SUM(cost) as monthly_cost
  FROM `project.dataset.gcp_billing_export_v1_XXXXXX`
  WHERE DATE(usage_start_time) >= DATE_SUB(CURRENT_DATE(), INTERVAL 6 MONTH)
  GROUP BY 1, 2
)
SELECT 
  service.description,
  month,
  monthly_cost,
  LAG(monthly_cost) OVER (PARTITION BY service.description ORDER BY month) as prev_month_cost,
  ROUND((monthly_cost - LAG(monthly_cost) OVER (PARTITION BY service.description ORDER BY month)) / 
        NULLIF(LAG(monthly_cost) OVER (PARTITION BY service.description ORDER BY month), 0) * 100, 2) as growth_rate
FROM monthly_costs
ORDER BY service.description, month;
```

### 3. 비용 이상 탐지

```sql
-- 일일 비용 급증 탐지
WITH daily_costs AS (
  SELECT 
    DATE(usage_start_time) as usage_date,
    service.description,
    project.id,
    SUM(cost) as daily_cost
  FROM `project.dataset.gcp_billing_export_v1_XXXXXX`
  WHERE DATE(usage_start_time) >= DATE_SUB(CURRENT_DATE(), INTERVAL 14 DAY)
  GROUP BY 1, 2, 3
),
cost_with_avg AS (
  SELECT *,
    AVG(daily_cost) OVER (
      PARTITION BY service.description, project.id 
      ORDER BY usage_date 
      ROWS BETWEEN 6 PRECEDING AND 1 PRECEDING
    ) as avg_cost_7days
  FROM daily_costs
)
SELECT *,
  ROUND((daily_cost - avg_cost_7days) / NULLIF(avg_cost_7days, 0) * 100, 2) as cost_spike_pct
FROM cost_with_avg
WHERE daily_cost > avg_cost_7days * 2  -- 평균의 2배 이상
  AND avg_cost_7days > 10  -- 기준 금액 이상에서만
ORDER BY cost_spike_pct DESC;
```
