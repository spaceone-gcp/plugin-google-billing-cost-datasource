# 자세한 데이터 내보내기의 구조

이 문서는 Google Cloud의 공식 [자세한 데이터 내보내기의 구조](https://cloud.google.com/billing/docs/how-to/export-data-bigquery-tables/detailed-usage?hl=ko) 가이드를 기반으로, 상세 사용량 비용 데이터의 완전한 스키마와 개별 리소스 수준 분석 방법을 설명합니다.

## 📋 개요

**상세 사용량 비용 데이터**는 표준 데이터의 모든 필드를 포함하면서도, 개별 리소스 수준까지의 세밀한 정보를 제공합니다. 이를 통해 VM 인스턴스, 디스크, 네트워크 등 각각의 리소스에 대한 정확한 비용 추적과 분석이 가능합니다.

### 테이블 정보
- **테이블명**: `gcp_billing_export_resource_v1_<BILLING_ACCOUNT_ID>`
- **생성 조건**: 상세 사용량 비용 데이터 내보내기 활성화
- **포함 데이터**: 표준 데이터 + 추가 리소스 정보
- **업데이트 주기**: 일 1-2회
- **파티셔닝**: `usage_start_time` 필드로 일 단위 파티셔닝

## 🆚 표준 데이터와의 차이점

| 구분 | 표준 데이터 | 상세 데이터 |
|:---|:---|:---|
| **테이블명** | `gcp_billing_export_v1_*` | `gcp_billing_export_resource_v1_*` |
| **리소스 식별** | SKU 수준까지만 | **개별 리소스 수준** |
| **리소스 이름** | ❌ 제공 안 함 | ✅ `resource.name` |
| **글로벌 리소스** | ❌ 제한적 | ✅ `resource.global_name` |
| **상세 라벨** | 기본 라벨만 | ✅ 모든 라벨 및 시스템 라벨 |
| **태그 정보** | ❌ 제공 안 함 | ✅ 완전한 태그 정보 |
| **GKE 지원** | 기본적 | ✅ 고급 필터링 지원 |

## 📊 상세 데이터 전용 필드

### 1. 리소스 정보 (Resource)

| 필드명 | 타입 | 설명 | 활용 예시 |
|:---|:---|:---|:---|
| `resource.name` | `STRING` | 개별 리소스의 고유 이름 | VM 인스턴스, 디스크 등 개별 추적 |
| `resource.global_name` | `STRING` | 글로벌 리소스의 이름 | 글로벌 로드밸런서, CDN 등 |

```sql
-- VM 인스턴스별 월간 비용 분석
SELECT 
  resource.name as instance_name,
  project.id as project_id,
  location.zone,
  SUM(cost) as monthly_cost,
  AVG(usage.amount) as avg_core_hours
FROM `project.dataset.gcp_billing_export_resource_v1_XXXXXX`
WHERE service.description = 'Compute Engine'
  AND sku.description LIKE '%Instance Core%'
  AND DATE(usage_start_time) >= DATE_SUB(CURRENT_DATE(), INTERVAL 30 DAY)
  AND resource.name IS NOT NULL
GROUP BY instance_name, project_id, location.zone
ORDER BY monthly_cost DESC;
```

### 2. 시스템 라벨 (System Labels)

| 필드명 | 타입 | 설명 | 활용 예시 |
|:---|:---|:---|:---|
| `system_labels` | `RECORD` (반복) | Google Cloud 시스템에서 자동 생성하는 라벨 | 자동 분류 및 메타데이터 |
| `system_labels.key` | `STRING` | 시스템 라벨 키 | 시스템 속성 기반 필터링 |
| `system_labels.value` | `STRING` | 시스템 라벨 값 | 자동 태깅 정보 |

```sql
-- GKE 클러스터별 비용 분석 (시스템 라벨 활용)
SELECT 
  (SELECT value FROM UNNEST(system_labels) WHERE key = 'gke-cluster-name') as cluster_name,
  (SELECT value FROM UNNEST(system_labels) WHERE key = 'gke-nodepool-name') as nodepool_name,
  SUM(cost) as cluster_cost,
  COUNT(DISTINCT resource.name) as resource_count
FROM `project.dataset.gcp_billing_export_resource_v1_XXXXXX`
WHERE service.description = 'Kubernetes Engine'
  AND DATE(usage_start_time) >= DATE_SUB(CURRENT_DATE(), INTERVAL 7 DAY)
GROUP BY cluster_name, nodepool_name
HAVING cluster_name IS NOT NULL
ORDER BY cluster_cost DESC;
```

### 3. 태그 정보 (Tags)

| 필드명 | 타입 | 설명 | 활용 예시 |
|:---|:---|:---|:---|
| `tags` | `RECORD` (반복) | 리소스에 연결된 태그 정보 | 정책 기반 비용 할당 |
| `tags.key` | `STRING` | 태그 키 | 태그 기반 필터링 |
| `tags.value` | `STRING` | 태그 값 | 태그 값별 집계 |
| `tags.inherited` | `BOOLEAN` | 상위 리소스에서 상속된 태그 여부 | 태그 상속 관계 분석 |
| `tags.namespace` | `STRING` | 태그 네임스페이스 | 조직별 태그 관리 |

```sql
-- 태그 기반 비용 할당 분석
SELECT 
  (SELECT value FROM UNNEST(tags) WHERE key = 'cost-center') as cost_center,
  (SELECT value FROM UNNEST(tags) WHERE key = 'environment') as environment,
  (SELECT value FROM UNNEST(tags) WHERE key = 'owner') as owner,
  SUM(cost) as allocated_cost,
  COUNT(DISTINCT resource.name) as resource_count,
  COUNT(DISTINCT project.id) as project_count
FROM `project.dataset.gcp_billing_export_resource_v1_XXXXXX`
WHERE DATE(usage_start_time) >= DATE_SUB(CURRENT_DATE(), INTERVAL 30 DAY)
GROUP BY cost_center, environment, owner
HAVING cost_center IS NOT NULL
ORDER BY allocated_cost DESC;
```

## 🔍 개별 리소스 분석 활용 사례

### 1. VM 인스턴스 최적화 분석

```sql
-- 사용률이 낮은 VM 인스턴스 식별
WITH instance_usage AS (
  SELECT 
    resource.name as instance_name,
    project.id as project_id,
    location.zone,
    SUM(cost) as total_cost,
    SUM(usage.amount) as total_core_hours,
    COUNT(DISTINCT DATE(usage_start_time)) as active_days
  FROM `project.dataset.gcp_billing_export_resource_v1_XXXXXX`
  WHERE service.description = 'Compute Engine'
    AND sku.description LIKE '%Instance Core%'
    AND DATE(usage_start_time) >= DATE_SUB(CURRENT_DATE(), INTERVAL 30 DAY)
    AND resource.name IS NOT NULL
  GROUP BY instance_name, project_id, location.zone
)
SELECT *,
  ROUND(total_core_hours / (active_days * 24), 2) as avg_utilization_ratio,
  ROUND(total_cost / NULLIF(total_core_hours, 0), 4) as cost_per_core_hour
FROM instance_usage
WHERE total_cost > 50  -- $50 이상인 인스턴스만
  AND total_core_hours / (active_days * 24) < 0.3  -- 30% 미만 사용률
ORDER BY total_cost DESC;
```

### 2. 스토리지 리소스 분석

```sql
-- 디스크별 비용 효율성 분석
SELECT 
  resource.name as disk_name,
  project.id as project_id,
  location.region,
  sku.description as disk_type,
  SUM(cost) as monthly_cost,
  AVG(usage.amount) as avg_gb_hours,
  ROUND(SUM(cost) / NULLIF(AVG(usage.amount) / (24 * 30), 0), 4) as cost_per_gb_month
FROM `project.dataset.gcp_billing_export_resource_v1_XXXXXX`
WHERE service.description = 'Compute Engine'
  AND sku.description LIKE '%Storage%'
  AND DATE(usage_start_time) >= DATE_SUB(CURRENT_DATE(), INTERVAL 30 DAY)
  AND resource.name IS NOT NULL
GROUP BY disk_name, project_id, location.region, disk_type
HAVING monthly_cost > 10
ORDER BY cost_per_gb_month DESC;
```

### 3. 네트워크 리소스 분석

```sql
-- 로드밸런서별 트래픽 및 비용 분석
SELECT 
  resource.global_name as lb_name,
  project.id as project_id,
  SUM(CASE WHEN sku.description LIKE '%Forwarding Rule%' THEN cost END) as forwarding_rule_cost,
  SUM(CASE WHEN sku.description LIKE '%Data Processing%' THEN cost END) as data_processing_cost,
  SUM(CASE WHEN sku.description LIKE '%Data Processing%' THEN usage.amount END) as total_gb_processed,
  SUM(cost) as total_cost
FROM `project.dataset.gcp_billing_export_resource_v1_XXXXXX`
WHERE service.description = 'Compute Engine'
  AND (sku.description LIKE '%Load Balancing%' OR sku.description LIKE '%Forwarding Rule%')
  AND DATE(usage_start_time) >= DATE_SUB(CURRENT_DATE(), INTERVAL 30 DAY)
  AND resource.global_name IS NOT NULL
GROUP BY lb_name, project_id
ORDER BY total_cost DESC;
```

### 4. GKE 클러스터 상세 분석

```sql
-- GKE 노드풀별 상세 비용 분석
WITH gke_costs AS (
  SELECT 
    (SELECT value FROM UNNEST(system_labels) WHERE key = 'gke-cluster-name') as cluster_name,
    (SELECT value FROM UNNEST(system_labels) WHERE key = 'gke-nodepool-name') as nodepool_name,
    resource.name as node_name,
    location.zone,
    sku.description,
    SUM(cost) as cost,
    SUM(usage.amount) as usage_amount
  FROM `project.dataset.gcp_billing_export_resource_v1_XXXXXX`
  WHERE service.description IN ('Kubernetes Engine', 'Compute Engine')
    AND DATE(usage_start_time) >= DATE_SUB(CURRENT_DATE(), INTERVAL 7 DAY)
    AND EXISTS (SELECT 1 FROM UNNEST(system_labels) WHERE key = 'gke-cluster-name')
  GROUP BY cluster_name, nodepool_name, node_name, location.zone, sku.description
)
SELECT 
  cluster_name,
  nodepool_name,
  COUNT(DISTINCT node_name) as node_count,
  SUM(CASE WHEN sku.description LIKE '%Instance%' THEN cost END) as compute_cost,
  SUM(CASE WHEN sku.description LIKE '%Storage%' THEN cost END) as storage_cost,
  SUM(CASE WHEN sku.description LIKE '%Network%' THEN cost END) as network_cost,
  SUM(cost) as total_cost
FROM gke_costs
WHERE cluster_name IS NOT NULL
GROUP BY cluster_name, nodepool_name
ORDER BY total_cost DESC;
```

## 📈 고급 분석 패턴

### 1. 리소스 수명주기 분석

```sql
-- 리소스 생성/삭제 패턴 분석
WITH resource_lifecycle AS (
  SELECT 
    resource.name,
    project.id,
    service.description,
    MIN(DATE(usage_start_time)) as first_seen,
    MAX(DATE(usage_start_time)) as last_seen,
    COUNT(DISTINCT DATE(usage_start_time)) as active_days,
    SUM(cost) as total_cost
  FROM `project.dataset.gcp_billing_export_resource_v1_XXXXXX`
  WHERE DATE(usage_start_time) >= DATE_SUB(CURRENT_DATE(), INTERVAL 90 DAY)
    AND resource.name IS NOT NULL
  GROUP BY resource.name, project.id, service.description
)
SELECT 
  service.description,
  DATE_DIFF(last_seen, first_seen, DAY) + 1 as lifespan_days,
  COUNT(*) as resource_count,
  AVG(total_cost) as avg_cost_per_resource,
  SUM(total_cost) as total_cost
FROM resource_lifecycle
WHERE DATE_DIFF(last_seen, first_seen, DAY) >= 0
GROUP BY service.description, lifespan_days
ORDER BY service.description, lifespan_days;
```

### 2. 리소스 태그 준수도 분석

```sql
-- 태그 정책 준수도 체크
WITH resource_tagging AS (
  SELECT 
    resource.name,
    project.id,
    service.description,
    SUM(cost) as total_cost,
    -- 필수 태그 체크
    CASE WHEN EXISTS (SELECT 1 FROM UNNEST(tags) WHERE key = 'environment') THEN 1 ELSE 0 END as has_env_tag,
    CASE WHEN EXISTS (SELECT 1 FROM UNNEST(tags) WHERE key = 'cost-center') THEN 1 ELSE 0 END as has_cost_center_tag,
    CASE WHEN EXISTS (SELECT 1 FROM UNNEST(tags) WHERE key = 'owner') THEN 1 ELSE 0 END as has_owner_tag,
    ARRAY_LENGTH(tags) as total_tags
  FROM `project.dataset.gcp_billing_export_resource_v1_XXXXXX`
  WHERE DATE(usage_start_time) >= DATE_SUB(CURRENT_DATE(), INTERVAL 30 DAY)
    AND resource.name IS NOT NULL
    AND cost > 0
  GROUP BY resource.name, project.id, service.description, tags
)
SELECT 
  service.description,
  COUNT(*) as total_resources,
  SUM(has_env_tag) as resources_with_env_tag,
  SUM(has_cost_center_tag) as resources_with_cost_center_tag,
  SUM(has_owner_tag) as resources_with_owner_tag,
  ROUND(AVG(has_env_tag + has_cost_center_tag + has_owner_tag), 2) as avg_compliance_score,
  SUM(CASE WHEN (has_env_tag + has_cost_center_tag + has_owner_tag) = 3 THEN total_cost ELSE 0 END) as compliant_cost,
  SUM(total_cost) as total_cost
FROM resource_tagging
GROUP BY service.description
ORDER BY total_cost DESC;
```

### 3. 리소스 간 관계 분석

```sql
-- 프로젝트 내 리소스 종속성 분석
SELECT 
  project.id as project_id,
  project.name as project_name,
  service.description as service,
  COUNT(DISTINCT resource.name) as unique_resources,
  SUM(cost) as service_cost,
  -- 리소스 타입별 분포
  COUNTIF(sku.description LIKE '%Instance%') as compute_resources,
  COUNTIF(sku.description LIKE '%Storage%') as storage_resources,
  COUNTIF(sku.description LIKE '%Network%') as network_resources
FROM `project.dataset.gcp_billing_export_resource_v1_XXXXXX`
WHERE DATE(usage_start_time) >= DATE_SUB(CURRENT_DATE(), INTERVAL 30 DAY)
  AND resource.name IS NOT NULL
GROUP BY project.id, project.name, service.description
HAVING service_cost > 100
ORDER BY project.id, service_cost DESC;
```

## ⚡ 성능 최적화 팁

### 1. 효율적인 쿼리 패턴

```sql
-- 좋은 예: 파티션 필터 + 리소스 필터
SELECT resource.name, SUM(cost)
FROM `project.dataset.gcp_billing_export_resource_v1_XXXXXX`
WHERE DATE(usage_start_time) = '2024-01-15'  -- 파티션 필터
  AND resource.name IS NOT NULL              -- NULL 제외
  AND service.description = 'Compute Engine'  -- 서비스 필터
GROUP BY 1;

-- 피해야 할 예: 복잡한 UNNEST 연산
SELECT resource.name, 
       (SELECT value FROM UNNEST(tags) WHERE key = 'env') as env,  -- 비효율적
       SUM(cost)
FROM `project.dataset.gcp_billing_export_resource_v1_XXXXXX`
WHERE cost > 0  -- 파티션 필터 없음
GROUP BY 1, 2;
```

### 2. 대용량 데이터 처리

```sql
-- 샘플링을 통한 빠른 분석
SELECT 
  service.description,
  COUNT(*) * 100 as estimated_total_resources,  -- 1% 샘플 기준
  SUM(cost) * 100 as estimated_total_cost
FROM `project.dataset.gcp_billing_export_resource_v1_XXXXXX` TABLESAMPLE SYSTEM (1 PERCENT)
WHERE DATE(usage_start_time) >= DATE_SUB(CURRENT_DATE(), INTERVAL 30 DAY)
  AND resource.name IS NOT NULL
GROUP BY service.description
ORDER BY estimated_total_cost DESC;
```
