# 📝 문서 작성 규칙 및 금지 사항

## 📋 개요

Google Cloud Billing Cost Datasource Plugin 프로젝트의 모든 문서 작성 시 반드시 준수해야 할 규칙과 금지 사항을 정의합니다.

**적용 대상**: 모든 `.md`, `.mdc` 파일

---

## 🚫 엄격 금지 사항

### 1. 향후 처리 예정 주석 완전 금지

#### ❌ 절대 사용 금지 표현
```markdown
# 금지된 표현들
- TODO: 향후 구현 예정
- 예정: 다음 버전에서 추가
- 계획: 2024년 Q2에 개발
- 향후: 추후 업데이트 예정
- TBD: To Be Determined
- Coming Soon: 곧 제공 예정
- 준비 중: 현재 개발 중
- 개발 예정: Development planned
- 추후 추가: Will be added later
- 구현 계획: Implementation plan
```

#### ✅ 허용되는 대안 표현
```markdown
# 허용되는 표현들
- 현재 지원하는 기능: Currently supported features
- 구현 완료된 기능: Implemented features  
- 사용 가능한 옵션: Available options
- 지원되는 형식: Supported formats
- 현재 버전에서 제공: Available in current version
```

### 2. 미완성 내용 포함 금지

#### ❌ 금지된 내용 유형
- 구현되지 않은 기능 설명
- 계획만 있고 실제로는 작동하지 않는 코드 예시
- 존재하지 않는 파일이나 모듈 참조
- 테스트되지 않은 설정 방법
- 불확실한 정보나 추측성 내용

#### ✅ 허용되는 내용 유형
- 현재 작동하는 기능만 문서화
- 실제 테스트된 코드 예시만 포함
- 존재하고 접근 가능한 파일만 참조
- 검증된 설정 방법만 제공
- 확실하고 정확한 정보만 포함

### 3. 불확실한 표현 금지

#### ❌ 금지된 불확실 표현
```markdown
- 아마도 (probably)
- 예상됩니다 (expected)
- 가능할 것입니다 (might be possible)
- 추후 확인 (to be confirmed later)
- 대략적으로 (approximately, roughly)
- 아직 확인되지 않음 (not yet confirmed)
- 테스트 필요 (needs testing)
```

#### ✅ 허용되는 확실한 표현
```markdown
- 현재 지원합니다 (currently supports)
- 확인되었습니다 (confirmed)
- 테스트 완료 (tested)
- 검증됨 (verified)
- 작동합니다 (works)
- 지원하지 않습니다 (does not support)
```

## ✅ 문서 작성 필수 원칙

### 1. 완성도 원칙
- 모든 내용은 현재 시점에서 완전히 구현되고 테스트된 것만 포함
- 문서의 모든 예시는 실제로 작동하는 것만 제시
- 모든 링크는 실제 존재하는 파일이나 URL만 참조

### 2. 정확성 원칙
- 모든 기술적 내용은 실제 코드와 일치해야 함
- 설정 예시는 실제 환경에서 테스트된 것만 포함
- 버전 정보는 정확한 현재 버전만 명시

### 3. 현재성 원칙
- 과거형이나 미래형 대신 현재형 사용
- "현재 버전에서는", "이 기능은" 등의 현재 상황 설명
- 날짜 기반 정보는 마지막 업데이트 날짜와 함께 제공

## 📊 문서 검증 체크리스트

### 작성 전 확인 사항
- [ ] 문서화할 기능이 실제로 구현되어 있는가?
- [ ] 모든 코드 예시가 실제로 작동하는가?
- [ ] 참조하는 모든 파일과 링크가 존재하는가?
- [ ] 설정 방법이 실제로 테스트되었는가?

### 작성 중 확인 사항
- [ ] TODO, 예정, 계획 등의 표현을 사용하지 않았는가?
- [ ] 불확실한 표현(아마도, 예상 등)을 사용하지 않았는가?
- [ ] 모든 내용이 현재 시제로 작성되었는가?
- [ ] 미완성 기능에 대한 언급이 없는가?

### 작성 후 확인 사항
- [ ] 문서의 모든 예시를 실제로 실행해 보았는가?
- [ ] 모든 링크가 올바르게 작동하는가?
- [ ] 문서 내용이 최신 코드와 일치하는가?
- [ ] 마지막 업데이트 날짜가 정확한가?

```bash

grep -r -i "todo\|예정\|계획\|향후\|tbd\|coming soon\|준비 중" docs/ --include="*.md"
grep -r -i "아마도\|예상\|추후 확인\|대략적으로" docs/ --include="*.md"

grep -r -i "확인되었\|테스트 완료\|검증됨\|작동합니다" docs/ --include="*.md"

## 🛠️ 문서 수정 가이드라인

### 기존 문서 수정 시
1. **금지 표현 제거**: 모든 TODO, 예정 등의 표현 삭제
2. **미완성 내용 제거**: 구현되지 않은 기능 설명 삭제
3. **현재형 변환**: 모든 내용을 현재 시제로 변경
4. **검증 완료 내용만 유지**: 테스트되고 확인된 내용만 보존

### 새 문서 작성 시
1. **기능 구현 확인**: 문서화할 기능이 완전히 구현되었는지 확인
2. **테스트 수행**: 모든 예시와 설정을 실제로 테스트
3. **현재형 작성**: 모든 내용을 현재 상황 기준으로 작성
4. **검증 체크리스트 실행**: 위의 체크리스트 모든 항목 확인

## 📚 예시: 올바른 문서 작성

### ✅ 좋은 예시
```markdown
# BigQuery 연동 가이드

## 현재 지원하는 기능
- BigQuery 테이블에서 직접 데이터 조회
- 표준 빌링 데이터 및 상세 사용량 데이터 지원
- 자동 타입 변환 및 정밀도 개선

## 설정 방법
다음은 실제 작동하는 설정 예시입니다:

```yaml
options:
  billing_export_project_id: "your-project"
  billing_dataset_id: "billing_export"
```

이 설정은 현재 버전에서 테스트 완료되었습니다.
```

### ❌ 나쁜 예시
```markdown
# BigQuery 연동 가이드

## TODO: 향후 지원 예정 기능
- 실시간 스트리밍 데이터 처리 (2024년 Q2 예정)
- AI 기반 비용 예측 (개발 계획 중)
- 멀티 클라우드 통합 (TBD)

## 설정 방법
아마도 다음과 같이 설정하면 작동할 것입니다:

```yaml
options:
  # 추후 확인 필요
  streaming_mode: true  # 아직 구현 안됨
```

이 기능은 추후 업데이트 예정입니다.
```
