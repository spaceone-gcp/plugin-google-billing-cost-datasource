## 🛠️ 문서 관리 원칙

### 1. 문서 생성 기준
- ✅ 새로운 주요 기능 추가 시
- ✅ 복잡한 설정이나 프로세스가 생길 때
- ✅ 기존 문서가 너무 길어져서 분리가 필요할 때 (400줄 이상)
- ✅ 특정 사용자 그룹을 위한 전용 가이드가 필요할 때

### 1.1 문서 작성 금지 사항
- ❌ **향후 처리 예정 주석 금지**: "TODO:", "예정:", "계획:", "향후:" 등
- ❌ **미완성 내용 포함 금지**: 구현되지 않은 기능이나 계획만 있는 내용
- ❌ **불확실한 정보 금지**: "아마도", "예상", "추후 확인" 등의 표현
- ❌ **임시 플레이스홀더 금지**: "TBD", "Coming Soon", "준비 중" 등

### 2. 품질 기준
- ✅ **정확성**: 코드와 일치하는 정보
- ✅ **완전성**: 필요한 모든 정보 포함
- ✅ **명확성**: 이해하기 쉬운 설명
- ✅ **최신성**: 최근 변경사항 반영
- ✅ **일관성**: 다른 문서와 용어 및 스타일 통일
- ✅ **완성도**: 향후 처리 예정 내용 주석 금지 (TODO, 예정, 계획 등)

### 3. 업데이트 정책
- **코드 변경 시**: 관련 기술 문서 동시 업데이트
- **새 기능 추가 시**: 사용자 가이드 및 API 문서 업데이트
- **버그 수정 시**: 트러블슈팅 가이드 업데이트
- **성능 개선 시**: 성능 최적화 문서 업데이트
