# 버전 히스토리 및 개선사항

## 📋 개요

Google Cloud Billing Cost Datasource Plugin의 버전별 주요 개선사항과 기술적 진화 과정을 문서화합니다.

## 🚀 Version 2.0 (2025-09-17) - 통합 Source 파라미터 및 Credits Detail 기능

### 🎯 주요 목표
- 통합된 source 파라미터로 모든 데이터 소스 통일
- Credits Detail 기능으로 완전한 크레딧 정보 제공
- gRPC 메시지 크기 최적화로 대용량 데이터 안정 전송
- 100% cost 필드 보장 시스템 구축
- 현대적 Python 환경 지원 (pyproject.toml)

### 🔧 핵심 개선사항

#### 1. 통합 Source 파라미터 시스템 ⭐ **NEW**
**문제점**: 복잡한 데이터 소스 설정과 `data_source_type` 혼재

**해결책**: 단일 `source` 파라미터로 통합
```yaml
# Before (복잡한 설정)
options:
  data_source_type: "http_file"
  bucket_name: "..."
  
# After (통합된 설정)
options:
  source: "gcs"  # "bigquery", "gcs", "http"
  bucket_name: "..."
```

**지원 데이터 소스**:
- `source: "bigquery"` - BigQuery 실시간 쿼리
- `source: "gcs"` - GCS 버킷 직접 처리 (신규)
- `source: "http"` - HTTP URL 파일 처리

#### 2. Credits Detail 기능 ⭐ **NEW**
**문제점**: BigQuery GROUP BY 집계로 인한 크레딧 세부 정보 손실

**해결책**: Credits Detail 모드 추가
```yaml
task_options:
  credits_detail_mode: true  # 완전한 크레딧 정보 제공
  credits_detail_limit: 50
```

**기능 비교**:
- **기본 모드**: 최적화된 성능, 크레딧 총액만 제공
- **Credits Detail 모드**: 개별 크레딧 정보 완전 제공

**응답 예시**:
```json
{
  "additional_info": {
    "Credits Detail": [
      {
        "name": "100% discount for Network Intelligence Center",
        "amount": -3.075138,
        "type": "DISCOUNT"
      }
    ]
  }
}
```

#### 3. gRPC 메시지 크기 최적화 ⭐ **NEW**
**문제점**: ResourceExhausted 오류 (4MB 제한)

**해결책**: 스마트 청킹 시스템
- 배치 크기 5개로 긴급 감소
- 실시간 메시지 크기 모니터링
- 자동 배치 크기 조정

#### 4. Cost 필드 100% 보장 시스템 ⭐ **NEW**
**문제점**: 과학적 표기법(9.6e-05) 등으로 인한 cost 필드 누락

**해결책**: 5단계 보장 시스템
1. **main.py**: gRPC 응답 전 최종 검증
2. **cost_manager.py**: BigQuery 응답 생성 시 보장
3. **field_mapper.py**: 필드 매핑 시 보장
4. **모든 parser**: 파일 파싱 시 보장
5. **BigQuery SQL**: 쿼리 레벨에서 보장

**과학적 표기법 지원**:
```python
# Before: 9.6e-05 → cost 필드 누락
# After: 9.6e-05 → 완벽하게 처리하여 cost 필드 보장
```

```python
# 비용 및 사용량 필드 정밀도 개선
if any(field in col.lower() for field in ['cost', 'amount', 'price', 'rate', 'usage_quantity']):
    standardized_df[col] = pd.to_numeric(standardized_df[col], errors='coerce').fillna(0.0)
```

**적응형 정밀도 알고리즘**:
```python
def _get_precision_by_value_range(abs_value):
    if abs_value >= 1000:    return 2   # 큰 값: 소수점 2자리
    elif abs_value >= 1:     return 6   # 중간 값: 소수점 6자리  
    elif abs_value >= 0.001: return 9   # 작은 값: 소수점 9자리
    else:                    return 12  # 극소 값: 소수점 12자리
```

```python
def test_decimal_to_float_conversion():
    """Decimal → float 변환 테스트"""
    test_cases = [
        (Decimal("0.000004846000000000001"), 0.000004846),
        (Decimal("1.8267580000000003"), 1.826758),
        (Decimal("1187.3999430000001"), 1187.40),
    ]
    
    for decimal_input, expected in test_cases:
        result = manager._decimal_to_clean_float(decimal_input)
        assert abs(result - expected) < 1e-15
```
