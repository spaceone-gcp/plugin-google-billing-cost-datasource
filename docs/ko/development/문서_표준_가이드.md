## 🚫 엄격 금지 사항

### 1. 향후 처리 예정 주석 완전 금지

#### ❌ 절대 사용 금지 표현
```markdown
<!-- TODO: 추후 작성 예정 -->
<!-- 향후 업데이트 예정 -->
<!-- 나중에 추가할 예정 -->
<!-- 개발 중 -->
<!-- 작성 중 -->
<!-- TBD (To Be Determined) -->
<!-- TBA (To Be Announced) -->
<!-- 추후 보완 -->
<!-- 미완성 -->
<!-- 임시 -->
```

#### ✅ 허용되는 대안
```markdown
<!-- 현재 버전에서는 지원하지 않음 -->
<!-- v2.1에서 추가 예정 -->
<!-- 구체적인 버전과 함께 명시 -->
```

### 2. 불완전한 문서 게시 금지
- 작성 중인 문서는 커밋하지 않음
- 모든 섹션이 완성된 후에만 추가
- 빈 섹션이나 placeholder는 삭제 후 커밋

### 3. 중복 정보 최소화
- 같은 내용을 여러 파일에 반복 작성 금지
- 참조 링크를 활용하여 중복 제거
- 단일 정보원(Single Source of Truth) 원칙 준수

## 📝 문서 작성 표준

### 1. 파일 명명 규칙

#### **한국어 파일명 사용**
```
✅ 올바른 예시:
- 로깅_표준_가이드.md
- API_명세서.md
- 버전_히스토리_및_개선사항.md

❌ 잘못된 예시:
- logging_guide.md
- api_specification.md
- version_history.md
```

#### **언더스코어(_) 사용**
- 공백 대신 언더스코어 사용
- 영어 단어는 PascalCase 또는 camelCase 허용

### 2. 문서 구조 표준

#### **필수 섹션**
모든 가이드 문서는 다음 구조를 따라야 합니다:

```markdown
# 📚 문서 제목

## 📋 개요
- 문서의 목적과 범위 명시
- 마지막 업데이트 날짜 포함

## 🎯 주요 내용
- 핵심 내용 섹션들

## 📚 관련 문서
- 관련 문서들에 대한 링크

---

**마지막 업데이트**: YYYY년 MM월 DD일
**버전**: vX.X.X
**주요 기능**: 간단한 기능 요약
```

#### **이모지 사용 규칙**
- 섹션 제목에 적절한 이모지 사용
- 일관된 이모지 사용 (📋 개요, 🎯 목표, 📚 관련 문서 등)
- 과도한 이모지 사용 지양

### 3. 링크 및 참조 표준

#### **내부 링크 형식**
```markdown
- **[문서 제목](./파일명.md)**: 간단한 설명
- **[API 명세서](../technical/API_명세서.md)**: API 상세 스펙
```

#### **외부 링크 형식**
```markdown
- [공식 문서](https://example.com): 외부 리소스 설명
```

### 4. 코드 블록 표준

#### **언어 지정 필수**
```markdown
✅ 올바른 예시:
```python
def example_function():
    return "Hello World"
```

```bash
# 명령어 실행
python script.py
```

❌ 잘못된 예시:
```
def example_function():
    return "Hello World"
```
```

#### **주석 및 설명 포함**
```python
# ✅ 권장 방식
def calculate_cost(usage_data: dict, rate: float = 0.1) -> float:
    """비용을 계산합니다."""
    return usage_data.get("amount", 0) * rate
```

## 🔄 문서 업데이트 프로세스

### 1. **업데이트 주기**
- **코드 변경 시**: 관련 문서 즉시 업데이트
- **버전 릴리스 시**: 모든 문서 검토 및 갱신
- **월 1회**: 전체 문서 일관성 점검

### 2. **업데이트 절차**
1. **변경사항 식별**: 코드 변경이 문서에 미치는 영향 분석
2. **관련 문서 수정**: 영향받는 모든 문서 업데이트
3. **크로스 참조 확인**: 링크 및 참조 정확성 검증
4. **버전 정보 갱신**: 마지막 업데이트 날짜 및 버전 정보 수정

### 3. **품질 검증**
- **내용 정확성**: 기술적 내용의 정확성 확인
- **링크 유효성**: 모든 내부/외부 링크 동작 확인
- **일관성**: 용어, 형식, 스타일 일관성 검증
- **완성도**: 모든 섹션의 완성도 확인

## 📊 문서 품질 관리

### **품질 지표**
1. **완성도**: 모든 섹션이 완성되었는가?
2. **정확성**: 기술적 내용이 정확한가?
3. **최신성**: 최신 버전을 반영하고 있는가?
4. **일관성**: 다른 문서와 일관된 형식인가?
5. **유용성**: 사용자에게 실질적 도움을 주는가?

### **정기 점검 항목**
- [ ] 모든 링크가 정상 작동하는가?
- [ ] 코드 예제가 최신 버전에 맞는가?
- [ ] 스크린샷이나 이미지가 최신인가?
- [ ] 버전 정보가 정확한가?
- [ ] 중복된 내용이 있는가?

### **문서 개선 원칙**
1. **사용자 중심**: 사용자의 관점에서 작성
2. **단계별 설명**: 복잡한 과정은 단계별로 분해
3. **예제 포함**: 실제 사용 가능한 예제 제공
4. **문제 해결**: 일반적인 문제와 해결책 포함
5. **지속적 개선**: 사용자 피드백 반영
