# 코드 유지보수 가이드

## 개요

이 문서는 SpaceONE Google Cloud Billing Cost Datasource 플러그인의 코드를 수정할 때 반드시 따라야 할 절차와 규칙을 정의합니다.

## 코드 수정 후 필수 처리 사항

### 1. 🔍 Ruff 검사 및 수정

모든 코드 수정 후에는 반드시 Ruff를 사용하여 코드 품질을 검사하고 문제를 수정해야 합니다.

#### 자동화 스크립트 사용 (권장)
```bash
# 가상환경 활성화 후 자동화 스크립트 실행
source venv/bin/activate
./scripts/check_code_quality.sh
```

#### 수동 검사 절차
```bash
# 1. 가상환경 활성화
source venv/bin/activate

# 2. 핵심 파일들에 대해 린트 검사 및 자동 수정
ruff check src/plugin/main.py src/plugin/manager/field_mapper.py src/plugin/parser/base_parser.py src/plugin/manager/cost_manager.py --fix

# 3. 코드 포맷팅 적용
ruff format src/plugin/main.py src/plugin/manager/field_mapper.py src/plugin/parser/base_parser.py src/plugin/manager/cost_manager.py

# 4. 최종 검사 (복잡도 경고 제외)
ruff check src/plugin/main.py src/plugin/manager/field_mapper.py src/plugin/parser/base_parser.py src/plugin/manager/cost_manager.py --ignore C901
```

#### 주요 검사 항목
- **코딩 스타일**: PEP 8 준수
- **Import 정렬**: isort 호환 순서
- **복잡도 관리**: Cyclomatic complexity ≤ 10 (경고 수준)
- **공백 처리**: 불필요한 공백 제거
- **네이밍 규칙**: snake_case, PascalCase 준수

#### 복잡도 경고 처리
일부 핵심 함수들은 비즈니스 로직의 복잡성으로 인해 복잡도 경고(C901)가 발생할 수 있습니다. 다음 함수들은 현재 허용된 복잡도 경고입니다:

- `FieldMapper._create_spaceone_billing_data()`: SpaceONE 빌링 데이터 구조 생성
- `BaseParser._sanitize_record_for_serialization()`: 레코드 직렬화
- `BaseParser.convert_value()`: 값 타입 변환

이러한 경고는 기능상 문제가 없으며, 향후 리팩토링 시 함수 분리를 고려할 수 있습니다.

### IDE Problems 해결 과정

IDE에서 표시되는 Problems를 체계적으로 해결하는 절차입니다.

#### 1. Problems 패널 확인
- VS Code/Cursor의 Problems 패널에서 오류와 경고 확인
- 파일별로 정리된 문제 목록 검토
- Import 오류, 복잡도 경고, 스타일 문제 등 분류

#### 2. 우선순위별 해결
1. **Import 오류 (빨간색 오류)**
   - SpaceONE 관련 import는 이미 Mock 처리됨
   - 실제 missing import가 있다면 해당 패키지 설치 또는 import 수정

2. **복잡도 경고 (노란색 경고)**
   - C901 복잡도 경고는 허용 수준
   - 필요시 함수 분리로 해결 (예: `_create_spaceone_billing_data` → 여러 헬퍼 함수)

3. **스타일 문제**
   - Ruff 자동 수정으로 해결
   - 포맷팅 문제는 `ruff format`으로 해결

#### 3. 검증 과정
```bash
# 자동화 스크립트로 모든 문제 한 번에 해결
source venv/bin/activate
./scripts/check_code_quality.sh

# 또는 수동으로 단계별 해결
ruff check [문제파일들] --fix
ruff format [문제파일들]
ruff check [문제파일들] --ignore C901
```

### 2. 🧹 디버그 로깅 정리

개발 과정에서 추가한 임시 디버그 로깅은 완료 시 반드시 제거해야 합니다.

#### 제거 대상
```python
# ❌ 제거해야 할 디버그 로깅 예시
_LOGGER.info(f"[DEBUG] 변수값: {variable}")
_LOGGER.debug(f"[디버깅] 처리 결과: {result}")

# 처음 N개만 로깅하는 임시 코드
if not hasattr(self, "_debug_count"):
    self._debug_count = 0
if self._debug_count < 5:
    self._debug_count += 1
    _LOGGER.info(f"DEBUG: {something}")
```

#### 유지해야 할 로깅
```python
# ✅ 유지해야 할 운영 로깅
_LOGGER.info("[CostManager] 파일 처리 시작")
_LOGGER.warning("[FieldMapper] 필수 필드 누락")
_LOGGER.error("[Parser] 파싱 실패", exc_info=True)
```

## 특별 주의사항

### SpaceONE 프레임워크 호환성
- **data 필드**: 반드시 딕셔너리 타입으로 유지
- **billed_date**: YYYY-MM-DD 형식 필수
- **직렬화**: 모든 데이터가 JSON 직렬화 가능해야 함

### 데이터 타입 일관성 (v2.1 업데이트)
- **data.listed_price**: 숫자 타입 (float) 사용 - 문자열에서 변경
- **data.cost**: 숫자 타입 (float) 사용 - 문자열에서 변경
- **기타 비용 필드들**: 모든 비용 관련 필드는 숫자 타입으로 통일
- **타입 일관성**: 최상위 cost 필드와 data 내부 필드 간 타입 일치
- **변환 함수**: `_convert_to_numeric()` 메서드로 안전한 숫자 변환 보장

### Google Cloud Billing 데이터 처리
- **Decimal 타입**: 비용 계산 시 정확성을 위해 Decimal 사용
- **중첩 구조**: BigQuery 중첩 필드 처리 고려
- **필드 매핑**: 다양한 소스 필드를 고려한 매핑

### 로깅 정책
- **운영 로깅**: INFO 레벨로 중요한 진행 상황 기록
- **에러 로깅**: ERROR 레벨로 예외 상황과 함께 스택 트레이스 포함
- **디버그 로깅**: 개발 중에만 사용, 완료 시 제거

## 자동화 스크립트

### 코드 품질 검사 스크립트
```bash
#!/bin/bash
# scripts/check_code_quality.sh

echo "🔍 Ruff 검사 시작..."
source venv/bin/activate

# 린트 검사
echo "1. 린트 검사 및 수정..."
ruff check src/ --fix

# 포맷팅
echo "2. 코드 포맷팅..."
ruff format src/

# 최종 검사
echo "3. 최종 검사..."
if ruff check src/; then
    echo "✅ 코드 품질 검사 통과!"
else
    echo "❌ 코드 품질 검사 실패!"
    exit 1
fi

echo "🧪 테스트 실행..."
if pytest; then
    echo "✅ 모든 검사 완료!"
else
    echo "❌ 테스트 실패!"
    exit 1
fi
```

## 버전 관리

### 커밋 메시지 규칙
```
타입(범위): 간단한 설명

상세 설명 (선택사항)

- 변경 사항 1
- 변경 사항 2

Closes #이슈번호
```

#### 타입
- `feat`: 새로운 기능 추가
- `fix`: 버그 수정
- `refactor`: 코드 리팩토링
- `docs`: 문서 업데이트
- `style`: 코드 스타일 변경
- `test`: 테스트 코드 변경
- `chore`: 빌드 설정, 도구 설정 등

### 브랜치 전략
- `main`: 안정적인 릴리즈 버전
- `develop`: 개발 중인 기능들
- `feature/*`: 새로운 기능 개발
- `fix/*`: 버그 수정
- `refactor/*`: 코드 리팩토링

## SpaceONE 응답 데이터 품질 보장 (v2.0 추가)

### 응답 데이터 검증 체크리스트

코드 수정 후에는 반드시 SpaceONE 응답 형태가 올바른지 검증해야 합니다.

#### 1. 필수 응답 구조 검증
- [ ] `{"results": [...]}` 구조가 유지되는가?
- [ ] `results` 배열의 각 레코드가 올바른 필드를 포함하는가?

#### 2. 필수 필드 존재 검증
```python
# 필수 필드 체크리스트
required_fields = [
    "cost",           # 숫자 타입
    "usage_quantity", # 숫자 타입  
    "provider",       # 문자열 ("google_cloud")
    "region_code",    # 문자열 (빈 문자열 허용)
    "product",        # 문자열 (서비스명)
    "usage_type",     # 문자열 (SKU 설명)
    "resource",       # 문자열 (리소스 식별자)
    "billed_date",    # 문자열 (YYYY-MM-DD 형식 필수)
    "tags",           # 딕셔너리 (빈 딕셔너리 허용)
    "additional_info", # 딕셔너리 (빈 딕셔너리 허용)
    "data"            # 딕셔너리 (SpaceONE 프레임워크 필수)
]
```

#### 3. 데이터 타입 검증
- [ ] `cost`: 숫자 타입 (int/float)
- [ ] `billed_date`: YYYY-MM-DD 형식 문자열
- [ ] `data`: 딕셔너리 타입 (필수)
- [ ] `data.listed_price`: 숫자 타입 (float)
- [ ] `data.cost`: 숫자 타입 (float)

#### 4. JSON 직렬화 검증
- [ ] 모든 Pandas/NumPy 객체가 기본 Python 타입으로 변환되었는가?
- [ ] `json.dumps(response)` 실행 시 오류가 없는가?
